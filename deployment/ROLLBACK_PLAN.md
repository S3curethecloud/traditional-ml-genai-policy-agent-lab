# Phase 11 Rollback Plan

## Release scope

This rollback plan applies to the tutorial release candidate generated by the
Phase 11 supply-chain pipeline.

## Trigger conditions

Rollback is required when any of the following occurs after deployment:

- Workflow success SLO breach
- Unauthorized runtime attempt
- Cross-tenant control failure
- Policy-version mismatch
- Evidence-integrity failure
- Runtime timeout increase beyond the approved threshold
- Prompt or model regression
- Container health-check failure
- Deployment configuration mismatch

## Rollback target

Restore the previously approved:

- Application revision
- Model version
- Prompt version
- Policy version
- Runtime version
- Orchestrator version
- Production configuration
- Container image digest

## Procedure

1. Stop further promotion.
2. Preserve current workflow and deployment evidence.
3. Select the previous signed release manifest.
4. Verify its SBOM, provenance, and checksum manifest.
5. Restore the previous immutable application artifact.
6. Restore the corresponding pinned configuration.
7. Run smoke and policy-boundary tests.
8. Verify runtime remains inaccessible without `ALLOW`.
9. Verify cross-tenant requests remain denied.
10. Record the rollback outcome and incident reference.

## Data compatibility

This tutorial phase performs no database migration.

A production release containing data migration must include explicit forward
and backward compatibility evidence.

## Authority boundary

This document defines a rollback procedure. It does not execute a rollback,
grant approval, or override deterministic policy.
