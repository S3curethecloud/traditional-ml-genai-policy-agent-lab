# Phase 2 — Synthetic Incident Dataset

## Purpose

This phase creates a reproducible labeled dataset for teaching traditional machine learning without using customer, production, or sensitive operational data.

The dataset is intentionally synthetic.

It is suitable for:

- Feature exploration
- Classification tutorials
- Train, validation, and test splitting
- Data-quality demonstrations
- Baseline-versus-ML comparisons
- Reproducibility exercises

It is not suitable for production decision-making.

## Dataset Categories

The dataset contains six balanced incident categories:

1. `authentication_failure`
2. `deployment_regression`
3. `infrastructure_saturation`
4. `network_degradation`
5. `dependency_failure`
6. `unknown`

Each category receives the same number of generated records.

The default configuration generates 100 records per category, producing 600 total records.

## Feature Distributions

Each incident category has a category-specific feature distribution.

### Authentication Failure

Typical characteristics include:

- Elevated login failures
- Elevated token-validation errors
- Moderate latency
- No recent deployment requirement

### Deployment Regression

Typical characteristics include:

- A deployment in the previous 30 minutes
- Elevated login failures or HTTP 5xx errors
- Elevated latency
- Potential multi-region impact

### Infrastructure Saturation

Typical characteristics include:

- CPU utilization at or above 90 percent
- High memory utilization
- Elevated latency
- Possible server errors

### Network Degradation

Typical characteristics include:

- Packet loss at or above 3 percent
- Elevated latency
- Moderate HTTP failures
- Normal CPU and memory behavior

### Dependency Failure

Typical characteristics include:

- Elevated downstream dependency errors
- Elevated HTTP failures
- Increased latency
- No required deployment relationship

### Unknown

Typical characteristics include:

- No dominant incident pattern
- Rates below category thresholds
- Low or moderate user impact
- Single-region scope

Reproducibility

Generation uses a local pseudorandom number generator with a fixed seed.

The default seed is:

42

Using the same generator version, record count, and seed must produce identical records.

The generator does not use:

Current time
Network calls
External APIs
Global random state
Production data
Split Strategy

The dataset uses deterministic stratified splitting:

Training: 70 percent
Validation: 15 percent
Test: 15 percent

Each category is split independently so that all six categories appear in every split.

The split seed is recorded in the dataset manifest.

Leakage Prevention

The lab prevents direct record leakage by verifying that incident identifiers do not overlap across:

Train and validation
Train and test
Validation and test

The feature set does not include:

Category names
Rule identifiers
Human-readable diagnosis text
Dataset split names
Labels encoded inside identifiers used for training

The incident_id is retained for traceability but must be excluded from model features.

Known Limitations

Synthetic data simplifies real incident behavior.

The generated distributions may be easier to classify than production incidents because:

Category boundaries are deliberately understandable
Missing data is limited
Telemetry noise is controlled
Labels are generated by known logic
Operational context is simplified
Correlated failure modes are underrepresented

Phase 3 must report these limitations when evaluating the ML classifier.

Phase Completion Criteria

Phase 2 is complete when:

Generation is reproducible.
Every category is balanced.
Every split contains every category.
Train, validation, and test identifiers do not overlap.
Invalid feature values are rejected.
Duplicate IDs are rejected.
Material class imbalance is rejected.
Generated files have recorded cryptographic hashes.
All Phase 2 tests pass.
